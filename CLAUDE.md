# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev      # start dev server (localhost:3000)
npm run build    # static export to /out
npm run lint     # ESLint via Next.js
supabase start   # local Supabase (Docker): applies supabase/migrations + seed.sql
supabase db reset  # re-apply migrations + seed locally
```

No test suite exists. Formatting is enforced automatically via Husky pre-commit hook (Prettier on `*.{js,css,html}`).

## Architecture

**PeloPelo Maceió** is a pet adoption site for Maceió, Alagoas, Brazil. It is a clone of the original Campina Grande app (`../pelopelo`) with its own partner ONGs, contacts and backend, plus a management panel for ONGs. It is a Next.js app with `output: "export"` (fully static), so there is no server runtime — public data is fetched at build time via `generateStaticParams` and async Server Components. Hosting: Cloudflare Pages.

The public pages are also **live**: the build output is the first paint (and what link previews/SEO see); then client components (`CatalogComponent`, `PetAoVivo`, `SemelhantesAoVivo`, `ParceirosAoVivo`) refetch from Supabase with the public key, so photo/status changes and new pets show immediately. A pet published after the last build has no `/adote/<slug>.html`: Cloudflare serves `404.html` (`src/app/not-found.js`), whose `PaginaNaoEncontrada` recognizes `/adote/<slug>` and renders the pet live. Keep build-time and live rendering consistent (e.g. `escolherSemelhantes` is deterministic, no shuffle).

### Pages

- `/` — home page: Hero → Catalog → About → Partners → Footer
- `/adote/[slug]` — pet profile (slug like `mel-12`, generated by the DB and immutable): PetProfile → SimilarPets → Partners → Footer
- `/painel/*` — client-side panel (Supabase Auth). Roles: `perfil.papel` = `admin` (everything) or `ong`; ONG members have `perfil.funcao` = `coordenacao` (everything for their ONG: adoption requests, team at `/painel/equipe`, ONG profile, pet status) or `voluntario` (creates/edits pets, ficha, photos; a DB trigger forces their new pets to `em_avaliacao` and rejects status changes). `usePainel()` exposes `isAdmin` and `isCoordenacao` (true for admin too). Dynamic ids use query strings (`/painel/pet?id=12`) because static export can't generate runtime routes; pages using `useSearchParams` are wrapped in `<Suspense>`.
- Animal `status`: `em_avaliacao | disponivel | em_processo | adotado | morador | falecido` (only `disponivel` is public). Internal data never goes on `animal` (its row is public when available): it lives in child tables like `animal_ficha`, which carry `ong_id` + composite FK `(animal_id, ong_id)` and get `ong_id`/`registrado_por*` from the `private.preencher_ong_e_autor()` trigger. Roadmap for the rest of V2 is in `~/.claude/plans/pensando-em-digitalizar-a-mellow-cat.md`.

### Data layer

- **`supabase/migrations/`** is the source of truth for the schema: tables `ong`, `perfil`, `animal`, `foto`, `adoption_request`, `votes`, `newsletter`, `site_estado`. All authorization is RLS (helpers `private.eh_admin()`, `private.minha_ong()`, `private.sou_coordenacao()` — kept in the non-exposed `private` schema so they aren't callable via `/rest/v1/rpc`); the browser only ever has the public key. In triggers, only call `private.*` after checking `current_user = 'authenticated'` in a separate `if` (Postgres doesn't guarantee OR/AND evaluation order). Migrations already pushed to the remote are immutable: add a new migration instead of editing an old one. Only `status = 'disponivel'` animals of active ONGs are public.
- **`supabase/functions/`** — Edge Functions for anything needing secrets: `cloudinary` (signed browser uploads into `pets/<id>/` / `ongs/<id>/logo`, deletions) and `convidar` (admin, or an ONG's coordenação acting only on volunteers of their own ONG — a recovery link grants account access, so anything wider would allow account takeover; creates users via `generateLink` and returns a `/painel/definir-senha?token_hash=…` link — no email/SMTP involved; also `definir_funcao` and `remover`). Deleting animals and changing the logo (`cloudinary` via service role, which bypasses RLS) re-check `podeCoordenarOng`. Both validate the user's JWT themselves (`verify_jwt = false`).
- **Auto-publish:** triggers on `animal`/`foto`/`ong` set `site_estado.alterado_em`; `pg_cron` calls `publicar_site()` every 5 min, which POSTs the Cloudflare deploy hook stored in Vault as `deploy_hook_url`.
- **`src/services/supabase.js`** — shared client (`db`) + build-time queries for the public site (`getAnimals`, `getPetBySlug`, `getOngs`). Rows go through `formatPet` in `utils.js`, which maps DB values to labels and sorts `foto` into `images`/`image` (public_ids).
- **`src/services/painel.js`** — all panel operations (CRUD, uploads, invites, health, meds, documents).
- **V2 care tables** (all ONG-scoped by RLS, never readable by `anon`): `evento_saude` (health timeline; a new event of the same type/product auto-resolves the previous reminder; `vencimentos(ate)` lists pending ones), `tratamento` + `dose` (schedules are immutable — "Alterar" closes and replaces; `doses_previstas(de, ate, p_animal)` generates slots in `America/Maceio`; a trigger rejects duplicate/invented/far-future slots and forces `dada_por`), `documento` + private Storage bucket `documentos` (path `ong/<ong>/<equipe|restrito>/<animal>/<uuid>.<ext>`, checked by a constraint and by `private.pode_acessar_documento()`; `restrito` is coordination-only). Animals changing to `adotado`/`falecido` close open treatments; animals with documents can't change ONG.
- **Dates:** use `dataLocal()` from `utils.js` for "YYYY-MM-DD" in the browser's timezone — never `toISOString().slice(0, 10)` (UTC flips to tomorrow after 21:00 in Maceió).
- **PWA:** `public/manifest.webmanifest` (linked only from `src/app/painel/layout.js`), `public/sw-painel.js` (registered by `PainelShell` in production, scope `/painel`, caches only `/_next/static`), `public/_headers` (no-cache for SW/manifest on Cloudflare).
- **Tests:** `supabase/tests/rls.sql` (single `DO` block ending in `RAISE EXCEPTION`, so everything rolls back; run with `supabase db query --linked -f`) and `supabase/tests/e2e_*.sh` (curl against the linked project; they create and clean up their own users/pets/files). Run them after any migration or Edge Function change.
- **`src/services/cloudinary.js`** — `imageUrl(publicId, 'thumb'|'mini'|'full')` builds delivery URLs with inline transformations; falls back to a placeholder when there's no photo.

### Component model

- **Server Components** (`src/sections/`): fetch data directly. `Catalog`, `SimilarPets`, `Partners` are async.
- **Client Components** (`src/components/`): marked `"use client"`. Interactive UI only.
- **Panel** (`src/components/painel/`): `PainelShell` holds session/perfil in context (`usePainel()`), guards routes and renders the nav; all panel styles live in `Painel.module.css` and override the heavy global `button`/`input` styles.
- `src/hooks/useDatabase.js` — single hook managing poll voting and newsletter subscription state. Persists via `localStorage`. Also drives the 5-theme color system by writing CSS custom property overrides onto `:root`.

### Styling

Global CSS custom properties define 5 color themes (`--base-1` through `--base-5`, `--primary-*`, `--secondary-*`). The active theme is switched at runtime by `useDatabase` → `updateColorTheme(n)`. Section layout uses utility classes defined in `global.css`: `.section`, `.section-content`, `.section.white`, `.section.primary-to-base`, etc. Components use CSS Modules (`.module.css` co-located files).

### Path alias

`@/*` resolves to `src/*` (configured in `jsconfig.json`).

### Environment variables

All three are public and required at build time (see `.env.local.example`; full setup in `README.md`):

- `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` — Supabase project for Maceió (project `pelopelomaceio`, ref `twgycsakwfczwucoyyoj`, São Paulo; new-style `sb_publishable_…` key).
- `NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME` — Cloudinary cloud name (for delivery URLs).

Cloudinary API key/secret live only as Supabase function secrets (`supabase secrets set`; locally in `supabase/functions/.env`, gitignored).

### City-specific places

When adapting copy or partners, these are the spots that carry city context: `src/app/layout.js` (metadata description), `src/app/adote/[pet]/page.js` (share description), `src/components/Adopt.js` (phone mask uses DDD 82), `src/sections/Footer.js` (Instagram link, currently a placeholder), and the ONGs seeded at the end of the initial migration (partners are otherwise managed in the panel).

### Roadmap

V2 phase 1 is done (roles, census, ficha, health record, medications with dose checklist, "Hoje" screen + PWA, private documents). Next, per the approved plan in `~/.claude/plans/pensando-em-digitalizar-a-mellow-cat.md`: phase 2 (post-adoption: adoption term PDF + 30/90-day follow-ups; foster homes `lar_temporario` + `estadia`, whose address must never live on `animal`), phase 3 (stock with minimums; costs and donations with a transparency report). Out of scope for now: public sponsorship of resident animals, email/WhatsApp notifications, offline sync.
